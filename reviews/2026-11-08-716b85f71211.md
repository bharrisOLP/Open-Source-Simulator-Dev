## Findings

1. minor: meow_gpu/src/meow_gpu/interface.py:221 and :247 (`complete_complex_pairs`). A mode is "complex" when
   |Re(neff)| and |Im(neff)| are above 1e-9 |neff| (`_is_complex`, :176), but pairs are matched with PAIR_TOL = 1e-7
   (:173). A mode with a real eigenvalue (an evanescent mode, neff = i kappa, or a propagating mode) is its own
   partner. If the solver gives it a rounding-level part above 1e-9 |neff| (Re(neff)/|neff| = Im(lambda) / (2 |lambda|),
   so this is most probable near cutoff, |lambda| small), the rule finds no partner group and "both" (the default,
   also of `photonsuite.eme(interface="conserving")`) appends `conjugate_partner` of it: the same E_t (conj(E) of a
   real eigenvector) with neff -conj(neff), that is, a copy of the mode itself (or of its backward version). A copy
   makes the interface system singular (`ValueError`) or ill-conditioned. The added modes are not checked with
   `_is_copy`. Evidence that it is rare: in meow-solver-arpack-2/-3.jsonl, 60 of 77 and 14 of 17 modes below cutoff are
   purely imaginary to 1e-9, and each unpaired complex mode there has `conjugate_swaps` 1 in the "full" search (a
   true cut); in meow-interface-7.jsonl `pair_modes_added` is 0 or 1 per row, and "both" changes T00 by 2.4e-9 or less.
   No test covers a real eigenvalue with noise. Fix: in `complete_complex_pairs` use `_is_complex(m, pair_tol)` (or
   skip a mode with |(-conj(neff)) - neff| < pair_tol |neff|), and do not add a partner that `_is_copy` (E_t
   parallel, same neff) finds in the set; add a unit test with a real-eigenvalue mode whose neff has a 1e-8 relative
   real part.
2. minor: meow_gpu/src/meow_gpu/interface.py:50-51 and meow_gpu/README.md:577: the physics text "the time reversal
   ... then the mirror z -> -z" is not correct. The time reversal (E -> conj(E), H -> -conj(H)) of a field
   E(x, y) exp(i k0 neff z) gives exp(-i k0 conj(neff) z) directly, that is, the mode (-conj(neff), conj(E), -conj(H)).
   A mirror z -> -z after it gives conj(neff) (the growing member) and also changes the signs of E_z and H_t, which the
   formula does not do. The formula and the code are correct (derived again from `fde.operator.fields`: g = i neff ->
   conj(g) for the partner, H = (-i / eta0) X -> -conj(H); the test compares it with `fields` and the assembled
   operator). Fix: remove "then the mirror z -> -z" (in both places).

## What the reviewer tried to break

- The conjugate-partner formula. Derived from `fde.operator.fields` (meow_gpu): E_z and H_t are real stencils of E_t
  divided by g = i neff, H_z is a real stencil, and H is multiplied by -i / eta0. For E_t' = conj(E_t) and neff' =
  -conj(neff), g' = conj(g), so E' = conj(E) and H' = -conj(H); the assembled operator is real for real eps (real
  stencils, no PML, no bend), so conj(E_t) is an eigenvector of conj(lambda) = -(neff')^2. Correct. Im(neff') =
  Im(neff), so the partner decays in +z; the distance |conj(lambda) - t| = |lambda - t| for the real target, so the
  added member is in the spectrum of the window and at the cut distance. <m', m'> = -conj(<m, m>) in the Yee product
  holds (E_x' H_y' = -conj(E_x H_y)). Only the explanatory text is wrong (finding 2).
- Lossy media: `_real_operator` checks Im(nx, ny, nz) == 0 exactly and skips the rule otherwise; with loss every mode
  is "complex", so the lossy test does exercise the skip (modes[:7] would get 7 partners without it). A PML or bend
  window raises in `_usable` / `_wrong_branch` before the rule. A purely imaginary neff is excluded by `_is_complex`.
  The open edge case is a real eigenvalue with rounding noise (finding 1).
- Count and memory: "both" adds at most the size of each cut group (one mode per cut pair; the rows show at most one
  mode over all cells); the star product handles different mode counts per cell (the -7 rows ran with 120 and 121).

  0 stays the fundamental.
