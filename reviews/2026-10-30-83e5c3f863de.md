## Findings

1. **major**: the normal of the averaging in sheared voxels has a bias, and the README gives a wrong reason for
   the slow TE convergence. Places: bands_gpu/src/bands_gpu/geometry.py:22 ("This is correct for sheared and for
   non-cubic voxels"), geometry.py:224 (the fitted gradient), bands_gpu/README.md:78 ("TE 3.0e-3, 1.35e-3"), and
   bands_gpu/tests/test_oblique.py:167 ("TE converges slower in both cells").
   - The fitted gradient 12 sum_i m_i n_i b_i is exact only for a linear eps. At a step interface in a sheared voxel
     it has a bias.
   - Evidence. Square lattice of rods (r 0.2, eps 12), k points X, M and (0.2, 0.1), 4 bands, reference: the
     rectangular cell at 256 x 256. Maximum TE error at n = 32 / 64 / 128 / 192:
     - Rectangular cell: 2.85e-3 / 8.6e-4 / 2.24e-4 / 6.2e-5 (second order).
     - Sheared cell (1, 0), (1, 1) with the normal of this change: 5.8e-3 / 2.08e-3 / 8.4e-4 / 5.2e-4 (about
       first order).
     - The same sheared cells with the analytic radial normal in the interface voxels (the same <eps> and <1/eps>):
       3.8e-3 / 1.2e-3 / 2.5e-4 / 1.55e-4.
   - Thus the TE error in the rectangular cell does not converge slowly. Most of the sheared-cell TE error (3.4x at
     n = 128 and 192) comes from the normal estimate, not from TE "in both cells".
   - TM does not use the normal. In the sheared cell, TM converges irregularly: 5.0e-4 / 9.5e-5 / 9.4e-5 / 4.4e-5 at
     n = 64 / 128 / 192 / 256 (rectangular: 3.2e-4 / 3.0e-5 / 9.3e-6).
   - Impact on the triangular cell (60 degree voxels) is smaller. For holes TE at 128, the triangular cell and the
     supercell agree to 3.2e-5 (I reproduced the README table). The general oblique TE path is the new feature,
     but no test catches this order loss: the test needs only a ratio of 1.8 from n = 16 to n = 64.
   - Fix, one of:
     - (a) Compute the normal so that it has no bias in a sheared voxel. For example, take the first moment over
       an isotropic region (a circle or sphere around the voxel center, as Meep does). Or use the analytic normal
       of the object (MPB uses the shape normal; cylinder, sphere and block have simple normals). Then add a
       test that the sheared TE error falls by more than 3x from n = 64 to n = 128.
     - (b) At a minimum, correct geometry.py:22, README.md:78 and test_oblique.py:167. Say that the fit is exact
       only for a linear eps. Say that sheared-voxel TE converges at about first order (give the numbers above).
       Add this to "Known limits".

## Fixes by the author
Fixes made by the author agent of the change on my request, checked and staged by the lead agent.

1 (major, normal bias). Fixed: in each voxel that exactly one object boundary crosses, the normal is the analytic
normal of the object at the voxel center (as MPB does); where several boundaries cross, the fitted gradient is the
fallback (`normal` method of each shape in bands_gpu/src/bands_gpu/geometry.py, the crossing count in
Cell._sample, the choice in eps_inverse, which also takes normal="fit" for comparisons). The docstrings, the README
and the test text are corrected. New test test_sheared_te_converges_at_second_order (sheared cell, reference
rectangular 192 x 192: object normal 1.21e-3 and 2.52e-4 at n = 64 and 128, ratio 4.8; fit 2.08e-3 and 8.38e-4,
ratio 2.5) and the CPU bench bands_gpu/bench/normal_order.py (table in the README: sheared TE error at n = 32 / 64 /
128 / 192: 3.81e-3 / 1.25e-3 / 2.98e-4 / 2.04e-4 with the object normal, against 5.86e-3 / 2.12e-3 / 8.77e-4 /
5.62e-4 with the fit). Above n = 128 the sheared TE error falls slowly with both normals (TM, which does not use the
normal, also converges irregularly there): a known limit in the README. Numbers of the rectangular path change for
TE and for curved 3-D objects (rods 32 x 32 TE up to 4.3e-4, spheres 12^3 up to 6.2e-4, more accurate against
finer grids); TM, the Bragg stack, slabs and homogeneous cells stay the same bit for bit, so tests/test_bands.py
and the rectangular README numbers (all TM) do not change. Triangular air holes at 128 agree with the supercell to
1.9e-5 (before 3.2e-5).

2 (non-cubic numbers). Fixed: test_non_cubic_voxels_against_a_cubic_reference states the case (rod r 0.3 at
(0.1, 0.2), cell 1 x 1.5, 24 x 20 voxels, TE, reference 96 x 144) and rebuilds the old first-moment normal; the
README numbers come from it: error 2.34e-3 (object normal), 4.12e-3 (fit), 8.53e-3 (old first moment); mean angle
error over all 40 interface voxels 0, 9.13 and 20.44 degrees.
