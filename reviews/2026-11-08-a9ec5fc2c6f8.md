## What the reviewer tried to break

- **Tests on the GPU computer**: the full fdtd_gpu suite gave 63 passed in 187 s, with 1 warning (the Drude film did
  not decay within max_time 300, as the README says). `test_dispersion.py` has 25 tests (15 without an FDTD run, 10
  with). The counts in the README (63, 36, 27) are correct.
- **ADE coefficients**: the reviewer derived the chi of the fdtdx recurrence. D (s - c1 - c2 / s) = w0^2 dt^2 -
  4 sin^2(w dt / 2) - i g dt sin(w dt), with s = exp(-i w dt). This is `chi_yee`: the standard central-difference ADE
  with E at step n (explicit), second order. fdtdx `update_E` (diagonal branch) gives eps_inf dE + dP = dt curl H,
  as the docstring says. The coefficients in `float32_coefficients` were checked. Keeping c1 + c2 keeps the
  resonance to first order, and the rounding of c1 goes into c2, which sets the damping. This agrees with the
  6e-8 / (g dt) statement.
- **Units**: f and gamma in c/a are multiplied by 2 pi C0 / UM to give rad/s. The Drude plasma frequency is
  w_n sqrt(sigma). These are the forms of the MIT package (frequency f_n, gamma = gamma_n / 2 pi). The conductivity
  is sigma = eps0 eps sigma_D (C0 / UM), scaled by C0 dt / courant (the same `conductivity_spacing` as fdtdx). With
  eps0 eta0 c = 1, the factor is b = sigma_D dt / 2. The logged decay agrees with (2 / dt) atanh(b) to 3.4e-6 and
  1.4e-5.
- **Sources**: in fdtdx `update_E` the sources come after the division by (1 + b). Thus the "(1 + b) too strong"
  statement is correct, and b = 0.0071 at res 20 for sigma_D = 0.5. The sources take their inverse permittivity in
  `apply_params`, before the ADE arrays exist, so they use 1 / eps_inf. The own path of fdtdx would use
  `effective_inv_permittivity` (1 / Re eps). This agrees with the claim.
- **Stability bound**: the reviewer derived x (eps_inf + sum K / (w0^2 - x)) = k^2, with x = (2 / dt)^2 sin^2(w dt / 2).
  Above the largest w0^2 the left side increases, and the condition at x = 4 / dt^2 gives the bound of the change.
  s = 0.327, 0.653 and 0.980 are correct, and so are res > 1.80 f_p / sqrt(eps - s), 12.7, 3.05, 2.19 and 76 / um.
  eps is the smallest eps of the cells of the material: eps_inf with the staircase rule, and smaller (so safer) with
  `AVERAGE_EPS_INF`. The bound is for a uniform medium (a von Neumann analysis), and the README states it as such.
- **fdtdx arrays**: c1 to c3 have the shape (poles, 1, *cells) and P has (poles, 3, *cells). These are the same as
  the own allocation of fdtdx (`initialization.py`: 1 component for isotropic poles; P in the field dtype, c in the
  config dtype). `ArrayContainer.reset()` sets P to zero and keeps c and the conductivity. Non-dispersive cells get
  c = 0 and P stays 0. `custom_fdtd_forward` uses the container as given. Conductive cells and dispersive cells are
  never the same cell, so the order of the ADE term and the division by (1 + b) does not matter.
- **Non-dispersive runs are unchanged**: the reviewer read the code paths. `staircase_at_lossy` returns the same
  array, and `material_arrays` is not called. The other additions are only checks that raise. Thus the arrays are
  bit-identical (finding 5 is a cost only). `rasterize` merges materials by identity, so a dispersive material and a
  plain material with the same eps_inf stay separate.
- **README numbers of checks 10 to 12**: the reviewer compared all of them with the 15 rows. All agree, except the
  items of finding 3. The checked values include orders 1.95 and 1.75, 2.02 and 2.00, the roots 0.4999 - 0.01i and
  0.552680 - 0.01i, 3.3e-5 = 6e-8 / (g dt), 7.4e-4 = 6e-8 / (w0 dt)^2 at res 400, and 7e-3 and 0.14 of the source
  peak at |f - 1| = 0.4 and 0.25.
- **Lead point 1**: see finding 1. The README phrase "the same 50 cells" is correct. The check detects a mixed
  rule at the face cells (a regression test). It does not detect the staircase error, because the snapped thickness
  is exact by construction. A thickness that is not a whole number of cells is the correct test, and it reverses
  the conclusion.
- **Lead point 2**: the mid-band part at res 400 is explained by the float32 coefficients (Yee grid with float32
  coefficients 4.2e-5, float64 3.3e-4). The reviewer's run with a wider source band confirms it (mid 3.1e-4). The
  band-edge part (1.1e-3) is a weak-source effect. Its mechanism is not shown (finding 2).
- **Hygiene and licenses**: the patch has no host names, IP addresses, private paths, e-mail addresses, client or
  PDK data. The media are synthetic, in the forms of Jackson, 3rd ed., Sec. 7.5 (the correct section). No fdtdx code
  is copied, and fdtdx (MIT) is in the license table of the top README.
- **Scratch files**: `rv8_emul.py` (the exact Yee-grid emulation, CPU) and `rv8_gpu.py` (the FDTD runs d = 0.504 and
  res 400 with fwidth 1.6) are in a reviewer scratch folder on the Mac. Copies are at `/tmp/rv8_emul.py` and
  `/tmp/rv8_gpu.py` on the GPU computer.
