## Findings

1. **major: patch 0004 does not make the NaN words of the source deposit equal those of the host in general.**
   addon_gpu/README.md:318 says "Patch 0004 makes the NaN words of the source deposit equal those of the host", and
   tools/env/addon_patches/README.md:70 says that the patch "changes only this door" and that only "the array path
   and the kernels" keep the NaN sign of the GPU. The deposit has one more device subtraction before the door:
   `real_part -= amp_im * c_im` in `meep_gpu/sources.py:1460` of the add-on (the formation of `real(A)`). With an
   amplitude whose imaginary part is not finite, `amp_im * c_im` is a NaN subtrahend, and the GPU inverts its sign
   there. The door of patch 0004 then keeps that (already inverted) NaN. Evidence (scratch script
   `/tmp/rev8_nan_door_check.py` on the GPU computer, pinned clone with the four patches, the helpers and the 84 cases
   (configurations, components, currents) of `meep_gpu/test_source_deposit.py`):
   - amplitude `1 + inf j`: 70 of 84 cases differ, 280 words (host `ffc00000`, device `7fc00000`);
   - amplitude `1 + nan j`: 84 of 84 cases differ, 336 words (host `7fc00000`, device `ffc00000`);
   - amplitude `inf + 0j` (the table of the add-on test): 0 of 84 cases, 0 words (the patch works for this case).
   The add-on test passes only because its `non-finite` table holds only `inf + 0j`. Fix: either send the
   subtraction at `sources.py:1460` through the same NaN-ordered subtraction (one more patched, pinned file), or
   limit the two README texts to the door (a NaN `real(A)` that the host and the GPU form with the same word) and
   name the remaining difference with these counts.

2. **minor: on a ROCm build the door now refuses a subtrahend that is not float64.**
   tools/env/addon_patches/0004-hip-nan-subtrahend-deposit.patch:51-52 (`"float64 a, float64 b"` in an
   `ElementwiseKernel`). CuPy raises `TypeError: Type is mismatched. b float32 float64` for a float32 array and the
   same for an int64 array, where the old in-place `wide -= real64` accepted both (and still does on the other
   builds). Python floats, 0-d float64 arrays and broadcast float64 arrays work as before (scratch script, part 4).
   The callers of the add-on form `real64` from complex128 amplitudes, so no present call fails. Fix: cast an array
   subtrahend with `astype(xp.float64, copy=False)` (exact), or state the float64 contract in the docstring of
   `_subtract_once`.

3. **minor: "only the 43 modules that it can change ran again" is an inference.** addon_gpu/README.md:317. The 43
   modules were chosen by text (they name `host_writes`, or they read the ledger entries that pin it). Each module
   that runs a source deposit on the CuPy route (through `sources._deposit`) also goes through the patched door. For
   finite operands the kernel gives the same words as the old subtraction (the 81 pairs of
   `tests/test_patches.py`, and 121 float64 pairs of the scratch script), so no count is expected to change. Fix:
   say "the 43 modules that name host_writes or read its ledger entries; the other modules reach the door only
   through the deposit, where finite words do not change".

4. **minor: the cause of the drift change 91 to 92 is named imprecisely.** addon_gpu/README.md:217 names the entries
   `bit_identity_gate` and `driver_dispatch`. Only `bit_identity_gate.source_sha256.meep_gpu/host_writes.py` is a
   raw-tier digest. `driver_dispatch.array_path_oracle.provenance_code_sha256` is a provenance map that the add-on
   reports and does not judge (`meep_gpu/array_path_oracle.py:52` of the add-on); the CUDA and Metal ledgers carry
   the same provenance pin. This explains why two pins give +1. Fix: name the one raw-tier entry, and say that the
   provenance pins are not judged.

5. **minor: the runner does not record the environment of a row.** The README (addon_gpu/README.md, "The whole test
   suite of the add-on") says that the run had `CUPY_GPU_MEMORY_LIMIT=8589934592`. `suite_runner.py` does not set
   it, and the rows do not record it. Only the run script of the last part of the run on the GPU computer exports
   it; for the earlier parts (02:54 to 03:35) no log shows it. Fix: write `CUPY_GPU_MEMORY_LIMIT` and
   `CUPY_CACHE_DIR` into each row (`run_module`, addon_gpu/suite_runner.py:184), or say in the README which parts
   had the limit.

6. **minor: the time limit of a module sends only SIGTERM.** addon_gpu/suite_runner.py:176 (`timeout <s>` without
   `-k`), and the same in the hold limit (`GPU_RUN_TIMEOUT`, tools/gpu_run.sh). A module that ignores SIGTERM is
   not stopped. The help text at addon_gpu/suite_runner.py:282 calls the limit "GPU_RUN_TIMEOUT of each module",
   but it is the `timeout` of the pytest call. Fix: `timeout -k 30 <s>`, and correct the help text.

7. **minor: the JUnit counts can differ from the pytest summary.** addon_gpu/suite_runner.py:133-141. A test that
   fails and also has a teardown error counts only as failed, and a passed test with a teardown error counts as an
   error, not as passed. The clean or not-clean result of a module does not change. Fix: one sentence in the
   docstring, or count the error elements separately.

8. **minor (text): small mismatches with the logs.** benchmarks/2026-11-08/README.md:18 names two modules for
   `addon-suite-default.jsonl` but the file has 3 rows; the third is `meep_gpu/test_dispatch_chunk_division.py`
   (03:28, which README note 8 cites). addon_gpu/README.md:147 and :307 say the last module started at 08:01; the
   last row started at 08:00:36. Fix: name the third module; write 08:00.

9. **minor (no action needed): the kernel does not quiet a signalling NaN.** Patch line 52 returns a NaN `a` or `b`
   as it is; x86 sets the quiet bit (32 of 121 float64 pairs differ, all with a signalling NaN operand). Through the
   door the rounding to float32 quiets the word on both sides: 0 of 30 stored words differ with signalling NaN
   stored words and subtrahends. A signalling NaN does not come from arithmetic. Optional: say "quieted" in the
   docstring.
