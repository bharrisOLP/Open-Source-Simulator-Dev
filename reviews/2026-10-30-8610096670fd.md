## Findings

1. **blocker** - `meow_gpu/src/meow_gpu/fde/eigensolver.py:426-429, 445, 418` (`refine`). The default `mixed`
   path can return the wrong eigenpair with `converged=True` when `num_modes` cuts a near-degenerate pair. The
   wanted set is fixed at step 1 by the distance of the complex64 Ritz values (residual 1e-3, `REFINE_SWITCH_TOL`)
   to the target. After step 1, `_track` follows each pair. The stop test uses `rn[:k]` of the tracked pairs, and
   `result()` sorts only `th[:k]`. An extra pair that converges nearer to the target than a wanted pair never
   comes back into the wanted set. At a residual of 1e-3, the complex64 Ritz values cannot order two eigenvalues
   that are closer than about the residual.
   Evidence (GPU, RX 7900 XT, `tests/structures.py` `coupler(gap=56)`, extra 4, tol 1e-10, the same x0 for the
   three solves; ARPACK order: TE even 2.1992470175, TE odd 2.1992469905, TM even 1.6732595472, TM odd
   1.6731713815):
   - K=1, seeds 0 and 1: refine gives neff 2.1992469905 (TE odd) with `converged=True`. Double and
     `polish="davidson"` give 2.1992470175 (TE even). |dneff| = 2.7e-8; |cos| of the fields with the double
     solve = 1.7e-4 and 4.8e-4 (an orthogonal mode). Seed 2: correct.
   - K=3, seed 0: refine gives TM odd 1.6731713815 as the third mode, with `converged=True`. Double and
     `polish="davidson"` give TM even 1.6732595472. |dneff| = 8.8e-5 (larger than the error of `single`);
     |cos| = 9.6e-9. Seeds 1 and 2: correct.
   - The earlier polish re-selects by the distance to the target at each step, so it was correct in all six
     runs. This is a regression of the default `mixed` path. `test_refine_separates_a_cluster` uses K=4, so both
     pairs are in the wanted set, and it cannot find this error. Symmetric structures (directional couplers in
     EME) with an odd `num_modes` are a normal use.
   Fix: at each step, select the k pairs nearest the target from all tracked pairs (for example
   `sel = argsort(|theta[:nb] - target|)[:k]`), use `rn[sel]` in the stop test and in the stall rule, and sort all
   b tracked pairs by distance in `result()`. All b pairs already get correction solves (`active = rn >= tol`),
   so the extras converge too. Add tests: the coupler with K=1 and K=3, seeds 0 to 2, against ARPACK and against
   the double solve (values and |cos| of the fields). Update the README section and the docstring of `refine`.
