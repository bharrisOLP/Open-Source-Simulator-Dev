## Findings

1. **major** - `meow_gpu/src/meow_gpu/fde/eigensolver.py:106-112` (`UNIFORM_SHIFT`, `_uniform`) and `:129-130`;
   `meow_gpu/README.md:789-794` ("A uniform window ... The test of the uniform step checks the convergence") and
   `:896` ("Closed: the solver misses modes above cutoff"). The shift is applied only when the window is
   *exactly* uniform (bitwise-equal real eps in all three components, mu = 1). A window that is uniform except for
   a small perturbation makes the preconditioner nearly exact. Without the wall unknowns, the solver then either does
   not converge, or converges to a set that misses a physical mode and gives no warning.
   - Evidence (scratch `rv_walls_nearuni_0811.py`, `rv_walls_nearuni2_0811.py`, `rv_walls_nearuni3_0811.py` on the
     GPU computer; 60 x 41 cells of 0.04 um, n = 1.444, 1.55 um, 6 modes, cold start, default `extra`; the reference
     is ARPACK shift-invert on A[R, R]):
     - No convergence (500 iterations, residual 0.6 to 1.6, wrong eigenvalues: the sorted distances to the target
       are off by 3.5e-3 to 3.3e-2 of |target|; only a warning) in single **and mixed** precision for: Im(eps) = 1e-8
       (uniform lossy cladding); one cell with eps * (1 + 1e-9) or (1 + 1e-6); eps_zz = eps (1 + 1e-8). Mixed also
       fails at one cell with eps * (1 + 1e-4) (residual 1.2e-2 after 500 iterations). For the same inputs, the
       search space of 505c4c5 (`make_preconditioner(q, deflate_walls=False)`) in mixed precision converged in 54 to
       86 iterations (to its full-matrix set, with wall modes). For mixed precision this is a regression.
     - A silent wrong set: one cell with eps * (1 + 1e-3) or (1 + 1e-2). Mixed and double give `converged=True`
       (residual <= 5.7e-11, no warning) with neff 1.40744, 1.364527, 1.325775 (twice), 1.202171, 1.20217. The
       physical eigenvalue at neff 1.291672 is nearer the target and is missing (distance error 1.1e-1 of |target|).
       In single precision this also occurs at eps * (1 + 1e-1) (distance error 9.7e-2). This is the failure that
       the README marks as closed. The 505c4c5 search space gave 4 wall modes and the 2 nearest physical modes there,
       so its result at 6 physical modes was not compared.
     - A Davidson-direction cause is probable (the same mechanism as the exact-uniform case of the docstring): when A
       - A0 is small or has a node at the modes, the correction adds almost no new direction.
     - The shift fixes all of these cases. With `make_preconditioner(q, eps_ref=0.99 * min Re eps)` for every
       problem (a monkeypatch, scratch 2), every case above gives the nearest set of A[R, R] (mixed: distance error
       <= 1.4e-14; single: <= 1e-6) in 5 to 18 iterations. The exact-uniform window and a window of two claddings
       (1.444 and 1.45, no core) also stay correct.
     - Tests and logged rows: `meow-interface-5.jsonl`, `meow-solver-arpack-2.jsonl` and the taper check below are
       not affected (cores with a strong contrast). The tests cover only the exact-uniform window
       (`tests/test_interface.py:149`) and the two taper cells.
   - Fix: make the shift robust, and do not depend on bitwise equality. For example, always use eps_ref =
     (1 - UNIFORM_SHIFT) min Re(eps). This changes only the iteration path, not the converged eigenpairs; check the
     speed rows again. Alternatively, apply the shift when max |eps_c - eps_ref| / eps_ref (for eps_xx, eps_yy and
     eps_zz, including Im) is below a threshold that covers the cases above. Add tests against ARPACK on A[R, R] for
     Im(eps) = 1e-8, one cell with eps * (1 + 1e-3), and eps_zz (1 + 1e-8), in mixed and single precision. Until the
     fix exists, qualify "Closed" in the README: near-uniform windows can still miss modes.

## What the reviewer tried to break

- Tests: `bash tools/gpu_run.sh meow_gpu python -m pytest -q` on the GPU computer: 132 passed (229 s).
- The decoupling, from the code. I derived it from `grid.axis_stencils` and `operator.apply`. With main[0] = 0 for
  a PEC near side (forward and backward), column 0 of Df and row 0 of Db are zero. Ex[:, 0] enters only its own rows,
  and its rows contain only Ex[:, 0]; the same holds for Ey[0, :]. PML divides by s, and a bend scales eps and mu,
  so neither changes the zeros. There are no unknowns on the far walls (Ex and Ey are not sampled at x_N or y_N). A
  PMC symmetry has main[0] != 0, so it has no wall unknowns. A PEC symmetry has walls, which is correct (tangential
  E = 0).
- The decoupling, numerically (scratch `rv_walls_struct_0811.py`). I used random complex media on non-uniform grids
  and 14 configurations:
  - straight; PEC symmetry on both axes, with and without far-side PML; PMC on both axes with PML; mixed PMC/PEC;
  - bends (axis 1 and 0, also with PEC or PMC symmetry and PML);
  - grids 1 x 17, 23 x 1, 2 x 2, 2 x 3 and 1 x 1.
