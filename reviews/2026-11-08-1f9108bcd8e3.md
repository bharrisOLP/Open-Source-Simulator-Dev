## Findings

No blocker and no major finding. The formulas are correct. The tests pass on the GPU computer, and each README
number that the reviewer checked agrees with a test print or a logged row. All findings are minor.

1. **minor**: `optics_gpu/README.md:355` (and the paragraph at 350 to 355). The README says "no test isolates
   the cause" of the Huygens peak difference (0.0245 for the image sum, 0.0269 for Optiland's HuygensPSF, 0.0280
   for the FFT PSF). The reviewer isolated most of it. The cause is the amplitude weight of the pupil samples, not
   an error in the normalization of `huygens_psf`.
   - Evidence (a scratch script on the GPU computer, singlet on the axis, pupil 256): a direct Debye sum over
     the pupil grid used the traced W, the exact image-side direction cosines and the same 80 x 80 grid of 1 um.
     - With a uniform weight for each entrance-pupil sample (the convention of the FFT PSF and of Optiland's
       HuygensPSF), the peak is 0.0287.
     - With the weight sqrt(J) (J: the area Jacobian of the map from the pupil to the image-side direction
       cosines; for this singlet J changes by 1.57x across the pupil), the peak is 0.0235. With the object-side
       factor of a flat angular spectrum also applied (1.1 % across the pupil), the peak is 0.0236. The image sum
       gives 0.0245 (0.0247 with 2x finer direction sampling).
     - Thus the weight choice alone moves the peak by about 18 %. About 4 % between 0.0236 and 0.0245 stays
       without a cause. The normalization (sum |a_r|)^2 is the in-phase peak of the same amplitudes (peak 1 for
       `ideal_relay`), so it is correct.
   - Fix: put these numbers into the README. Say that the "Strehl ratio" of `fft_psf` (and of Optiland) assumes
     a uniform amplitude for each entrance-pupil sample and a linear map to the direction cosines. Say also that
     the image sum uses energy-conserving sqrt(J) weights. A test could hold the two Debye sums.

Notes, no change necessary:

- For `ideal_relay`, the exit pupil is f - dz after the image surface (a virtual pupil). The code and Optiland
  trace each ray back by t ≈ R to the lens-side cap of the sphere, not to the cap through the exit-pupil point.
  The exact defocus formula and the "- dz / R" term are derived for that lens-side cap. The cap through the
  exit-pupil point would give "+ dz / R". The convention is consistent and the tests pin it.
- The off-axis orientation of the FFT PSF and the tangential direction (always y) follow Optiland. For a field
  along x, "tangential" is not the meridional direction. The README states both.

- **Reference sphere and sign.**
  - The center is the chief-ray image point and the radius goes to the paraxial exit-pupil point, the same as
    the Optiland "chief_ray" strategy (read in the installed source). Born and Wolf center the sphere on the
    Gaussian image point. The chief-ray choice (the lens-design convention) removes the distortion tilt, and
    the README names it.
  - Sign: W = (P_chief - P_ray) / lambda > 0 means that the ray reaches the sphere with a shorter path, so the
    wavefront is ahead of the sphere. This agrees with the exact defocus derivation (W > 0 for an image surface
    after the focus, where the real wavefront is more curved than the reference sphere).
  - The root choice in `_path_to_sphere` (the smallest t >= 0) is the same as Optiland's.
- **Exact defocus formula.** The reviewer derived it again. A spherical wave from the focus F, the reference
  center C at dz after F, and a ray at angle u give a sphere crossing at the signed distance
  s = dz cos u - sqrt(R^2 - dz^2 sin^2 u) on the lens-side cap. From this, W = s_0 - s =
  dz (1 - cos u) + sqrt(R^2 - dz^2 sin^2 u) - R, as in the README.
  - The series: dz t^2 rho^2 / 2 - 3 dz t^4 rho^4 / 8 - dz^2 t^2 rho^2 / (2 R).
  - rho^4 = Z9 / 6 + Z4 / 2 + Z1 / 3, so c4 = (a2 + a4) / 2.
  - With NA^2 = t^2 / (1 + t^2), c4 / (W020 / 2) - 1 = t^2 / 4 - dz / R to first order. The numbers 1.50e-3,
    3.50e-3 and -3.76e-4 agree.
  - R = f - dz: the exit pupil is the image of lens 1 through lens 2 at 2f, which is f - dz after the image
    surface.
  - The 1e-4 test tolerance is about 15x smaller than the effect, so the test can find a wrong formula.
- **FFT PSF sampling.** linspace(-1, 1, N) has N - 1 intervals across the diameter, so the pupil step is
  D / (N - 1). The DFT then gives dx = lambda z / (M delta) = lambda F (N - 1) / M. This is correct, and it is
  the same as Optiland's Q = M / (N - 1).
  - A wrong N (0.4 % scale at N = 256) would change the Airy check by about 2e-3, above its 1e-3 tolerance. The
    same is true for the MTF check, so the tests can find this error.
  - Working F-number: the same as Optiland's `get_working_FNO` (read in the source).
  - The PSF normalization by K^2 is the same as Optiland's `_get_normalization`.
- **MTF axis.** One pupil lag is n |dD| / ((N - 1) lambda), and the cutoff 2 NA / lambda is at lag N - 1. This
  is correct, and it is the same as Optiland's `_get_mtf_frequency_steps` for a flat image surface normal to z.
  The tangential slice is along y in both codes (the [ix, iy] and [iy, ix] orders agree). The perfect-lens test
  checks the step against 2 NA / ((N - 1) lambda) to 1e-12.
  - The README (2 N - 1) and the docstring (2 N) state different conditions for no wrap. Both are true, but see
    finding 5.
- **Zernike conventions.**
  - Fringe: the formula j = (1 + (n + |m|)/2)^2 - 2|m| + [m < 0] gives a bijection to the positive integers.
    The reviewer checked it by hand for j = 1 to 9, 36 = (10, 0) and 37 = (6, 6), and (12, 0) gives 49. The
    README statement about term 37 is correct.
  - Noll: the rule n(n + 1)/2 + |m| + c gives 1 to 11 as in Noll 1976 (Z5 = sin 2 phi, Z7 = sin phi, Z11 =
    (4, 0)). The normalization sqrt(n + 1) or sqrt(2 (n + 1)) is correct.
  - The values agree with Optiland to 1e-11. The orthonormality test passes.
- **Huygens normalization.** `huygens_psf` divides by (sum |a_r|)^2, which is the in-phase peak by the triangle
  inequality. The sqrt(J) weights of `trace_bundle` conserve energy for a Debye sum over a uniform grid of
  object directions. The cause of the 10 % difference is in finding 1. The image-sum peak changes by 0.7 % or
  less when the reviewer changed n_pad (32), n_src (128) and dx_src (0.5).
