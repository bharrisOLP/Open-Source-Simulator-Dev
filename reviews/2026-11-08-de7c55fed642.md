## Findings

1. **major**: `defocus` does not give the result of a trace to the moved image surface when the image space is a
   glass and the image surface has its default medium (air) after it. The claim is in
   `optics_gpu/src/optics_gpu/analysis.py:412` (docstring: "the same OPD map as a trace to the moved image
   surface"), `analysis.py:87-88` (item 8: "This is the same calculation as a trace to the moved image surface"),
   `optics_gpu/README.md:476-477`, and the limit in `optics_gpu/README.md:880-881` ("needs a flat image surface
   normal to z and one homogeneous medium after the last surface"). The tests check only an air image space.
   - Evidence (GPU computer, scratch scripts `/tmp/rev11_adv.py` part D and `/tmp/rev11_glass.py`): a singlet
     whose last gap is `IdealMaterial(n=1.4)` (image surface with no material) at 1.55 um, pupil 64.
     `defocus(wf, dz)` against `pupil_wavefront` of the optic with the image surface moved by dz = -80 and
     +80 um differs by 0.041 waves on the axis and by 0.073 waves at the object height 1 mm. The OPD peak to
     valley is 17 to 21 waves. The difference is a rho^2 term (fit: -0.0425 and +0.0415 waves rho^2).
   - Cause: Optiland's paraxial exit-pupil point (`exit_pupil_point_gcs`) of this optic moves with the image
     surface by dz (1 - 1/1.4). For dz = +80 um, z moves from 12.255748 to 12.278605 mm (22.857 um). Thus a new
     trace uses a sphere radius of 30.2435 mm, and `defocus`, which keeps the exit pupil fixed, uses 30.2663 mm.
   - Controls: the same optic with n = 1.0 agrees to 1.6e-11 waves. With the medium after the image surface also
     set to n = 1.4, it agrees to 2.5e-11 waves, and the exit pupil does not move.
   - Related pre-existing defect (item 2 of `pupil_wavefront`, not in this diff): the exit pupil that Optiland
     gives for this optic depends on the medium after the image surface (z 12.26 mm with air after it, 0.18 mm
     with n = 1.4 after it). Thus the reference-sphere radius of `pupil_wavefront` (30.1 mm against 50.0 mm)
     depends on a medium that the light does not enter. The tests compare against Optiland, which has the same
     exit pupil, so they do not see this.
   - Fix: state the condition in item 8, in the `defocus` docstring and in the README: the medium after the image
     surface must have the index of the image space, or both media must be air. Alternatively, refuse that case
     (store the index after the image surface in `PupilWavefront` and raise a ValueError in `defocus`). Add a
     test with a glass image space. Record the pre-existing exit-pupil dependence in the README limits.

- **The cache key.**
  - The same state gives the same key: `to_dict` is deterministic, and the key is the pickle with protocol 4.
    The test and my part B show that the same object is used again and that the result is bit for bit equal.
  - Different states give different keys if `to_dict` keeps the change. The key is computed in each call (0.017
    ms), so a mutated optic gets a new copy (test; my LRU loop of 10 thickness changes).
  - A change that `to_dict` does not keep gives the same key. The old code made the same copy from the same
    dictionary in that case, and the check rays still go through the original in each call. Thus the guard is
    not weaker than before.
  - The device is in the key (`cuda:N`). The dtype is fixed to float64 by `optiland_torch`.
  - The OrderedDict has no lock. Optiland's backend is already global and not thread-safe (the docstring of
    `pop.optiland_torch`), so this is not a new class of problem. A note in the README would help.
- **The kept paraxial path.**
  - In Optiland 0.6.3, `build_paraxial_path` reads only the frames and the mirror flags of the surfaces (the
    geometry). It does not use the wavelength or the field.
  - `ParaxialRayAimer.aim_rays` does not use the wavelength. Thus one path is valid for all wavelengths. The
    bench also agrees with Optiland at F, d and C to 3.5e-12.
  - With iterative and with robust ray aiming (these aimers keep state), I compared the kept copy repeated after
    another call, a new copy, and the batch against one call (part C). All are bit for bit equal for the
    dispersive singlet.
- **Bit for bit.** The test uses blocks of 1000 rays, so one block holds two fields. CPU and GPU are bit for bit
  equal (all tensors and numbers).
- **The `defocus` formula.** I derived it again from |Xp + u D - C'| = R'. The result is
  dW = n delta (1 - cos theta) / lambda - n delta^2 sin^2 theta / (2 R' lambda), with delta = dz / N_c. It is the
  same for an exit pupil on either side of the image, and it agrees with item 8 and with the README.
  - The README numbers 3.56e-3 (R' = 20.15 mm), 5.8e-4 and 3.62e-3 waves agree with this formula.
  - The chief ray: t0 = R exactly, because X = C for the chief ray, so s_c = R + dz / N_c is correct.
  - The sign of dz agrees with `moved()` (thickness + dz).
  - The asymmetry about the focus has the same sign as the Fresnel effect of an aperture at a finite distance
    (order dz / R). The README does not say which model is right physically, and that is acceptable.
  - The image-space medium gives finding 1.
- **The polychromatic weights.** By Parseval, sum_x |A|^2 = M^2 sum |P|^2. Thus the energy of a Strehl-unit PSF
  is (lambda F (N - 1))^2 sum(I) / K^2, and v_l ~ w_l K_l^2 / (lambda_l F_l)^2. This agrees with the code.
  - Numerical check (part H): v_l E_l / (w_l sum I_l) = 1.0595972e-3 for all three wavelengths.
  - u_l ~ w_l sum(I_l) is the OTF(0) of each term, so it is correct.
- **The matrix Fourier transform.**

  - The period is T = lambda F (N - 1).
  - The window rule h dx + max(|s_x|, |s_y|) <= T / 2, with h = M // 2, is correct for even and odd M.
  - For one wavelength, the default dx gives the FFT grid.
  - I compared the code with Optiland's `mmdft.py` (finding 4).
