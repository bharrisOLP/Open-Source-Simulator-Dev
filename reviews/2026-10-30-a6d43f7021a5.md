## Findings

### Major

1. **Wrong sign of the loss change (examples/pn_modulator.py:70; charge_gpu/README.md:39-40).** The code builds
   the material with k = dalpha lambda / (4 pi), k > 0 = absorption, and meow-gpu follows the tidy3d convention
   (keff >= 0 is loss; `meow_gpu/src/meow_gpu/meow_backend.py:104`). Reverse bias removes carriers, so dalpha <= 0
   in every cell and Im(dneff) < 0: the loss goes DOWN. The formula `-10 log10(e) 4 pi Im(dneff) / lambda` has an
   extra minus sign, so the example prints the loss decrease as a positive "dloss_dB_per_cm", and the README
   states "extra loss 1.0 to 2.8 dB/cm". Correct statement: the free-carrier loss decreases by 1.0 to 2.8 dB/cm
   at 1 to 4 V. Fix: remove the minus sign (dloss = +4.343 * 4 pi Im(dneff) / lambda_cm, negative here) and
   change the README text.

2. **Soref-Bennett hole term applied to a change from a non-zero baseline (charge_gpu/src/charge_gpu/modulator.py:36,
   used at examples/pn_modulator.py:46).** The fit dn_h = -8.5e-18 P^0.8 is a law of the absolute hole
   concentration (relative to intrinsic Si). It is not additive: dn(P0 -> P1) = -8.5e-18 (P1^0.8 - P0^0.8), not
   -8.5e-18 sign(dP) |dP|^0.8. In partly depleted cells the commit form overstates the index change (for
   P1 = P0/2: 0.574 vs 0.426 of P0^0.8, +35 %), and it inflates small changes. The usual workflow (carrier
   solver + mode solver) computes dn from the absolute N and P at each bias and then takes the difference.
   Repro: the same example with the absolute form (reviewer variant via runpy, everything else unchanged):
   V_pi L = 1.386 / 1.600 / 1.955 V cm at 1 / 2 / 4 V, against 1.172 / 1.437 / 1.829 V cm in the commit
   (Delta neff high by 18 %, 11 %, 7 %). The headline numbers in STATUS.md:63 and charge_gpu/README.md:39 (and
   the comparison "published 1.5 to 3 V cm") change. `test_plasma_dispersion_values`
   (charge_gpu/tests/test_junction.py:52) only checks changes from zero, so it cannot catch this. Fix: give
   `plasma_dispersion` the absolute concentrations (or P0 and P1) and difference the index; add a test with a
   non-zero baseline.

### Minor

3. charge_gpu/README.md:8-14: the usage snippet does not enable `jax_enable_x64`. Then `solve` silently runs in
   float32 (only a JAX truncation warning), cannot reach tol 1e-9 V and returns `converged=False` (repro: 1-D
   junction at 1 V without x64: 40 of 40 Newton steps, converged False). The exp clip at +-200
   (poisson.py:122-123) also overflows float32. Suggest: raise if float64 is not active, or enable it in the
   package.
4. charge_gpu/tests/test_junction.py:30: `n p = n_i^2` at zero bias is an identity of the model (phi_n = phi_p = 0),
   not a check of the solution. test_junction.py:29: the built-in potential check compares cell values next to the
   contacts with the Dirichlet values psi_b of the same contacts; it passes for almost any converged solution.
   STATUS.md:62 "exact built-in potential" and the README table overstate these two checks. The depletion-width
   and neutrality checks are the meaningful ones (the -2 V_T form is the exact charge-equivalent width with
   Boltzmann majority tails; verified by derivation).
5. charge_gpu/src/charge_gpu/poisson.py:175-178: the bias must be set twice (Contact.voltage and v_n / v_p) and
   nothing checks that they agree. A mismatch gives a silently wrong result. Suggest: set the contact
   potentials from v_n / v_p by the sign of the doping under each contact, or assert.
6. optics_gpu/tests/test_pop.py: no test checks the shape of the sqrt(J) weight. In the 4f system J is constant,
   and in the NA 0.075 singlet J is nearly constant, so only the global scale is tested (sqrt(J) vs 1/sqrt(J)
   differ only by a constant there). Also all cases are rotationally symmetric (orientation is not tested; the
   reviewer checked it, see below). Suggest: a high-NA or strongly non-uniform-J case and an off-axis source.
7. optics_gpu/src/optics_gpu/pop.py:67 and :101: object and image spaces are assumed to be air (L = lambda0 fx,
   k = 2 pi / lambda0). A source in glass or an image in an index-matching gel gives wrong results with no
   warning. Add this to the "Limits" (pop.py:19) and the README, or use n_obj and n_img.
8. optics_gpu/tests/test_pop.py:58: "all rays pass the 3 mm pupil" - the 4f system has no physical aperture
   (the EPD does not clip, as the README itself says). Wording only.
9. examples/chip_to_fiber_coupling.py:29: the SiN tip mode (neff 1.44696, n_clad 1.444) is limited by the
   +-4 um window: the field at the window edge is 10 % of the peak. Paraxial estimate of eta (mode vs the
   back-projected fiber Gaussian, w 2.08 um): 0.924 (+-4 um), 0.903 (+-5 um), 0.892 (+-6 um). The value
   "eta 0.929" in STATUS.md:55 is not converged against the window (about 4 % spread). Use a larger window or
   a less weakly guided tip.
10. optics_gpu/pyproject.toml: `optiland` is not pinned, and the tests and the example use APIs that Optiland
    marks for removal in v0.7.0 (`add_field`, `add_wavelength`, `image_solve`, `add_surface`). uv.lock pins it,
    but a fresh resolve will break. Pin `optiland<0.7` or move to the new API.
11. optics_gpu/README.md table: "coupling 1e-3" and "image radius 0.3 %" are observed values; the test
    tolerances are 2e-3 and 0.5 %. State the tolerances, or say "observed".

### Checked and correct (no finding)

- Angular spectrum: `np.fft.fft2` (e^{-i 2 pi f x}) times dx^2 with synthesis e^{+i k L x}; the roll puts x = 0 at
  index 0; the amplitude times df = dL dM / lambda^2. Consistent.
- sqrt(J) weight: |U'|^2 df' = |A|^2 df with df' = J df gives A sqrt(J) df per object-side sample. Correct.
- Optiland: `opd` accumulates n t in mm (standard_surface.py `_trace_real`), positions and W are scaled by 1e3 to
  um; physical apertures set intensity to 0 (`RealRays.clip`), which the `inten > 0` mask removes.
- Phase of each ray at the image point: W_r + L'(x - x_r) + M'(y - y_r) on a flat image surface. Correct.
- Poisson: sign of rho, F = A psi - b - rho V, Jacobian A + q (n + p) V / V_T (SPD), contact psi = V + V_T
  asinh(N / 2 n_i), phi_n = v_n (n contact), phi_p = v_p. Log damping is fine; convergence on the undamped step.
- V_pi L = V lambda / (2 |dneff|) with lambda in cm; alpha = 4 pi k / lambda with lambda in m and dalpha in 1/m;
  Soref-Bennett 1.55 um coefficients (8.8e-22, 8.5e-18 ^0.8, 8.5e-18, 6.0e-18) and the sign of the hole term.
- Public hygiene: no private paths, host names, e-mail addresses or client data in the diff; both lock files
  use only pypi.org / files.pythonhosted.org.
