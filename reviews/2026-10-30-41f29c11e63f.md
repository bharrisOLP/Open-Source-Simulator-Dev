## Findings

No blocker and no major finding. The physics, the discrete operator, the Galerkin coarsening and the numbers in
the README are correct, with the minor exceptions below.

1. **minor** - `thermal_gpu/src/thermal_gpu/multigrid3d.py:26-28`: the claim "largest eigenvalue of B A for the
   V-cycle 1.3 there, 1.7 in other random cases" is wrong in general. Evidence: on 60 random hierarchies (sizes
   5 to 13 per axis, aspect ratios 0.03 to 30 per axis, log-uniform and two-phase contrast, random Robin sides,
   coarsest 1 to 64 cells), the V-cycle has lambda_max(B A) up to 28.9; 39 of 60 cases are above 2. The cause is
   the over-correction 1.6 on semi-coarsened levels: a mode that changes only along a non-aggregated axis is exact
   on the coarse level, so the factor 1.6 overshoots, and it compounds per level (1.6^7 = 27; the worst case has
   8 one-axis levels). The V-cycle stays positive definite (lambda_min >= 0.03 in all cases; it is also provable,
   because the coarsest pinv is positive semi-definite), so the results are correct. But the condition number
   grows with the number of semi-coarsened levels, which probably explains the V-cycle growth 41 / 62 / 88
   iterations on the heater better than "deep hierarchy" alone. A simple change of the scalar (1.3 on all levels)
   gives 44 iterations instead of 41 at 100 nm, so there is no easy fix. Fix: remove the "1.7" claim, and state
   the mechanism in the docstring and in the README limit (`README.md:136-137`).
2. **minor** - `multigrid3d.py:26-28`, `README.md:137-138`, `tests/test_steady3d.py:215`: the W-cycle is said to be
   "not proven" positive definite. It is provable: with damped Jacobi (omega 0.8, lambda(D^-1 A) <= 2 by Gershgorin
   for these diagonally dominant operators) and the coarse two-step C = 2B - BAB, induction gives
   lambda(C A_c) in (0, 1] and lambda(B A) in (0, 1 + 0.6) = (0, 1.6] on each level. Measured maximum on the 60
   random hierarchies: 1.599, minimum 0.057. Fix (optional): state the bound, and use `top = 1.6 + 1e-9` instead of
   `np.inf` in the test, so that the test checks the bound.
3. **minor** - `README.md:56` and `README.md:130`: "3 to 4 s" for the first GPU solve with the V-cycle. The JSON rows
   give 3.72, 2.85 and 3.50 s (heater) and 2.80, 0.80 and 2.01 s (cube). Fix: "1 to 4 s" (or "2.9 to 3.7 s" for the
   heater).
4. **minor** - `README.md:54` and `multigrid3d.py:24`: the W-cycle runs "at half the CPU time". The JSON CPU rows
   give 2.231 / 5.894 = 0.38 at 50 nm and 12.194 / 34.021 = 0.36 at 25 nm (0.65 at 100 nm). Fix: "at about 0.4 of the
   CPU time".
5. **minor** - `README.md:73` (and the CLAIMS line "with Robin/Dirichlet sides"): the numbers 3e-10 (V), 2e-10 (W),
   1.4e-9 (Jacobi) are from the "top" case only. The parametrized "all" case (Dirichlet and Robin on the x and z
   sides) measures 4.0e-10 (V), 3.1e-10 (W), 2.6e-9 (Jacobi). Fix: give the larger value of the two cases, or add
   the second case to the table.
6. **minor** - `thermal_gpu/src/thermal_gpu/fv3d.py:65` and `fv3d.py:83-96`: input checks have gaps (the same gaps
   as the 2-D `fv.py`). ("robin", 10.0) and ("dirichlet",) give IndexError, not ValueError; h = 0 gives
   ZeroDivisionError; h = -5 is accepted and gives `converged = True` with a non-physical field; a NaN cell edge
   passes the edge check (np.diff(e) <= 0 is False for NaN) and fails later in pinv with LinAlgError. Fix: check the
   length of each spec, h > 0, and np.all(np.isfinite(e)).
7. **minor (test gap)** - `tests/test_steady3d.py:64`: the two-layer test has equal cells on both sides of the
   interface (2.0 um / 200 = 0.3 um / 30 = 10 nm), so it does not check the series formula with d1 != d2. The
   reviewer ran the same test with random non-uniform cells in both layers and a Robin max side: flux error 2.7e-12,
   3.0e-12 and 3.1e-12 along x, y and z. So the code is correct; the test can include this case.
