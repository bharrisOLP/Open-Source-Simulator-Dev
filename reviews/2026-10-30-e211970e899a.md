## Findings

1. **major: the half-step H shift is wrong; fdtdx already gives H at the time of E.**
   fdtd_gpu/src/fdtd_gpu/simulation.py:253-256 (`_phasors`) and fdtd_gpu/README.md ("DFT and flux": "fdtdx records
   H half a time step after E; fdtd-gpu moves H back by that half step").
   - Evidence (fdtdx 0.6.3 source): all detectors have `exact_interpolation=True` by default
     (fdtdx/objects/detectors/detector.py:36). `update_detector_states` (fdtdx/fdtd/update.py:1075-1085) gives the
     detector `H_avg = (H_prev + H) / 2`, where `H_prev` is H before the E update of the step
     (fdtdx/fdtd/forward.py:121). That average is H^(n+1/2) and H^(n+3/2): it is centered on the time of E^(n+1).
   - Evidence (run on the GPU computer): 1-D vacuum, plane current sheet, flux plane 3 um from the source. Without
     the shift, arg(Hy/Ex) is below 1.7e-4 rad at all frequencies (res 20 and 40). With the shift, arg(Hy/Ex) is
     exactly pi f dt (0.036 to 0.144 rad at res 20, 0.6 to 1.6 / um). A forward plane wave in a lossless medium has
     E and H in phase, so the shift adds a phase error of pi f dt.
   - Effects: (a) The false backward mode coefficient abs(alpha-)^2 / abs(alpha+)^2 of the 2-D strip (res 20) is
     1.1e-3 to 2.4e-3 with the shift and 0.44e-3 to 1.33e-3 without it. The README gives the co-located H on the
     Yee grid as the only cause; more than half comes from this shift. (b) abs(alpha+)^2 / input flux is 1.0008 to
     1.0018 with the shift and 1.0001 to 1.0009 without it. (c) The comment at simulation.py:253-254 ("else
     Re(E x conj H) is low by cos(omega dt / 2)") is wrong: without the shift the flux is HIGH (1-D sheet against the
     exact flux abs(I)^2 / 4: 1.0014 to 1.022 at res 20, 1.0006 to 1.0045 at res 40, second order). The shift
     multiplies the flux by about cos(pi f dt), and this partly cancels that O(dx^2) excess. (d) The dipole check
     agrees in part because of this cancellation: res 10 gives 1.0014 to 1.0023 with the shift and 1.0022 to 1.0060
     without it (res 20: 1.0007 to 1.0013 against 1.0006 to 1.0015). R and T ratios (Bragg, T_mode) do not change.
   - Fix: remove the shift (or set `exact_interpolation=False` and then derive and test a correct time and space
     alignment). Correct the README "DFT and flux" and "Mode coefficients" paragraphs. Add a test that checks
     arg(H/E) = 0 and the absolute flux of a 1-D current sheet against abs(I)^2 / 4 (an exact, cheap reference).
     Then state the absolute flux error of the Yee grid (O((k dx)^2)) in the README, and update the dipole and
     back_in numbers and rows.

2. **major: in 2-D, `eig_parity=EVEN_Z` (TE, Hz) gives NaN fields or the wrong mode, with no error.**
   fdtd_gpu/src/fdtd_gpu/simulation.py:327-336 (`_filter_pol`) and :400-405 (the mode source).
   - Evidence (run on the GPU computer, 2-D strip n 3.45 in 1.45, res 15): an `EigenModeSource` with `EVEN_Z` gives
     NaN in all monitor phasors. With the 2-D strip of the test case (res 20), the monitor mode with
     `eig_parity=EVEN_Z` (filter_pol "te") is the Ez mode (E fractions x, y, z = 0, 0, 1): the fdtdx filter finds
     no matching mode and falls back to the mode of the highest index. In 3-D the parities are correct (EVEN_Z:
     Ey 0.74, Ez 0.02; ODD_Z: Ez 0.75, Ey 0.05).
   - The README says only that the Hz case "is not tested". A 2-D TE script of the MIT package (EVEN_Z) is common;
     here it runs and gives NaN or a TM result.
   - Fix: raise NotImplementedError for `EVEN_Z` (an in-plane mode) when the cell has a trivial axis, in the
     source and in `get_eigenmode_coefficients`, or check the polarization fraction of the solved mode and raise
     if it does not match. Add a test for the error.

3. **minor: `EigCoeffs.neff` is always 0.** fdtd_gpu/src/fdtd_gpu/simulation.py:317. The code reads `det._neff`, but
   the fdtdx attribute is `_mode_neff` (fdtdx/objects/detectors/mode.py:221). The run printed
   `neff [[0. 0. 0. 0. 0.]]`; the correct values are 3.117 to 3.215 for the 2-D strip. Fix: read `_mode_neff`, and
   add an assert on neff to the waveguide test (compare with `references.slab_te_neff` in 2-D).

4. **minor: `Prism(center=...)` uses the center of the bounding box.** fdtd_gpu/src/fdtd_gpu/geometry.py:205-218.
   The documentation of the MIT package (Python interface, Prism) puts `center` at the centroid of all the
   vertices (the reviewer did not find the page online in this review; verify). For an asymmetric polygon (for
   example the triangle of test_geometry.py) the two points differ by 1/3 um, so a ported script moves the prism
   with no error. Fix: use the mean of the vertices, or list the difference in the README "Differences" section.

5. **minor: README numbers with no JSON row.** fdtd_gpu/README.md, checks 4 and the test line. No row in
   benchmarks/2026-10-30/fdtd-gpu.jsonl for: the dipole at res 10 (1.0014 to 1.0023; this review reproduced
   1.00139 to 1.00235), the box of half width 0.5 um at res 10 (0.7 to 1.9 %), the box without trapezoid weights
   (12 to 13 %), "11 passed in 75 s" (this review: 11 passed in 77.6 s), and the test comment "about 0.06 at 40"
   (test_validation.py:17). Also, rows that use the default resolution have no `resolution` field (bragg, both
   waveguide rows, the first ring and dipole rows), and the bragg row has no `cells`. Fix: always write the
   resolution and cells in bench_fdtd.py (bench_fdtd.py:46), and add rows for the numbers above or remove them.

6. **minor: the 3-D T_flux explanation is not tested.** fdtd_gpu/README.md check 2 and test_validation.py:32-35.
   The test checks the 3-D T_flux at the center frequency only, and the README says that the low band-edge values
   (0.983, 0.989) come from radiation of a mode source that is solved at one frequency. This is plausible, but no
   run separates it from the coarse grid (4.4 cells across the core). Fix: one row at a higher resolution, or a
   narrower band, that shows the cause; or say "probable cause" in the README.

7. **minor: Harminv `amp` and `err` are not the quantities of the MIT package.** fdtd_gpu/src/fdtd_gpu/harminv.py:15-20.
   `amp` is the amplitude of the shifted and filtered complex signal (half of the real cosine amplitude, with the
   FIR gain), and `err` is one residual for the whole fit. Fix: say so in the README "Harminv" paragraph.

- Gaussian source: fdtdx `GaussianPulseProfile` is exp(-(t - t0)^2 / (2 s^2)) cos(2 pi f t) with
  s = 1 / (2 pi spectral_width) and t0 = 6 s. With spectral_width = fwidth / (2 pi), s = 1 / fwidth, as the README
  says. `GaussianSource.fourier_transform` agrees with the analytic transform of that pulse (both terms).
- DFT convention: the fdtdx PhasorDetector sums field x exp(+i omega t) x stride ("pulse" mode); the code scales it
  by dt / sqrt(2 pi). Correct for the convention of the MIT package. The H shift is wrong (finding 1).
- Point-source amplitude: fdtdx adds -S inv_eps a to E and uses E += S inv_eps curl(H) with normalized H; so
  a = dx J and J = A / dx^zero is correct in 1-D, 2-D and 3-D.
- Dipole reference: derived again from the dipole fields in a medium (k = n omega, eps = n^2): the time average is
  n omega^2 abs(I)^2 / (12 pi); the DFT-convention flux is twice that, n omega^2 abs(I)^2 / (6 pi). Correct.
- Mode coefficients: derived again with E = a+ Em + a- Em-, Ht- = -Ht+: alpha+- = a+- sqrt(N), so abs(alpha)^2 is
  the flux. Correct. The forward and backward roles agree with the run (back_in is small).
- Mode monitor: fdtdx solves the mode at each monitor frequency (mode.py:349-373), not only at the center.
- Polarization filter: fdtdx "te" selects E along the first tangential axis. In 3-D, EVEN_Z gives Ey and ODD_Z
  gives Ez (correct). In 2-D, EVEN_Z fails (finding 2).
- Ring reference: the 4 x 4 boundary matrix (Ez and dEz/dr continuous; J, Y inside the ring, H1 outside) is
  correct for TM; exp(-i omega t) with H1 gives Im f < 0. The slab equation tan(kx w / 2) = gamma / kx is the
  correct even TE slab mode (used only to guess m). The assignment of m to the nearest exact resonance is safe:
  errors are 0.5 % or less and the free spectral range is about 4 %.

  dipole (res 20, res 30, n 1.5) numbers agree with the rows. Missing rows: finding 5.
- Trapezoid weights and box closure: the faces of the dipole box share the edge cells in the co-located grid of
