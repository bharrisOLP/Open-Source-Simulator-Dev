## Findings

No blocker and no major finding. Each minor finding of reviews 2026-11-08-cfae980e777a and 2026-11-08-f39279a5164e
has a fix in PATCH, except finding 7 of cfae980e777a (note 4 below). Every README number that the reviewer checked
agrees with the logged rows or with the test prints of the reviewer's run. Three minor findings and two notes:

1. minor, suite/src/photonsuite/pin.py:365-387 (`device_temperatures`): a weight with no cell gives NaN with no
   error. Example: with `pin_rib(background=-1e16)`, |N_D - N_A| = 1e22 m^-3 is not below the default threshold
   `intrinsic=1e22` (strict "<"). Then `mean()` divides 0 by 0, "intrinsic" is NaN (only a RuntimeWarning), and
   the `--weights` bench solves at T = nan. The logged rows are not affected (background 1e15 cm^-3). Fix: raise
   ValueError when `np.sum(w) == 0`, or use "<=" and say so in the docstring.
2. minor, suite/tests/test_fdtd_avg.py:96-114 (`test_the_calibrated_path_of_a_straight_guide`): the straight guide
   makes the three runs the same simulation, so b_in = b_out and T00 = T00_raw. The test cannot detect a swap of
   b_in and b_out, a calibration run of the wrong cross-section, or the inverse ratio b_out / b_in. Only the bench
   rows (b_in differs from b_out) use the path with different guides. The README text is accurate ("the same
   simulation as the device run here"). Fix (optional): a short two-segment device with different widths at a low
   resolution. Check that the input-plane index of `calibration[0]` equals the run's `neff_in`, and that the
   output-plane index of `calibration[1]` equals the run's `neff_out`.
3. minor, suite/bench/pin_self_heating.py:95: `seconds` is measured before the per-bias rows. Thus the summary rows
   of `suite-pin-4.jsonl` (51.26 s and 50.05 s) do not include the 66 weight solves of each lifetime. These solves
   have no logged time, and the index row of benchmarks/2026-11-08/README.md gives only the clock window (20:07 to
   20:10). No README number depends on this time. Fix (optional): log the time of the weight solves per row.
4. note (not in PATCH): finding 7 of cfae980e777a (the `input_mode_share` docstring "below 1") is fixed only in the
   uncommitted fdtd_avg.py of another agent (not in PATCH, not reviewed here). It lands only with that change. The
   module text of fdtd_avg.py ("Mode coefficients") has no sentence about the Yee-flux bias. Finding 2 asked for one
   sentence, and the suite README now has it, so that finding is closed.
5. note: the test bounds of `test_pin_phase_shifter_two_way_to_the_end` (T within 2e-4 K, I' rel 1e-5, dneff rel
