## Findings
No blocker and no major finding. All findings are minor (documentation accuracy, test margin, robustness).

1. minor: charge_gpu/README.md:260 and charge_gpu/src/charge_gpu/injection.py:73 (`rib_pin`). The README says
   "20 nm cells give 8.6 % less current at 0.9 V". This is mostly a change of the geometry, not a grid error.
   With dx = 20 nm the cell centers fall on the boundaries, so the default rib has an 80 nm slab (not 90 nm) and
   p+ / n+ widths of 0.94 / 0.96 um (not 0.95 / 0.95). The test fixture (tests/test_drift_diffusion.py:170,
   20 nm, half_span 1 um, clad 0.2 um) has a 100 nm slab and p+ / n+ of 0.44 / 0.46 um (reviewer scratch run on
   the GPU computer). The 10 nm and 5 nm grids give the true geometry, and their JSONL rows differ by 0.05 to 0.1 %
   (current) and 0.02 to 0.06 % (n rib). So "converged to about 0.5 %" is true, but the 20 nm number does not
   support it. Fix: say that the 20 nm grid changes the slab to 80 nm (or remove the sentence), and let `rib_pin`
   put the boundaries on cell edges or raise an error when dx does not divide slab, height, width/2 and gap.
2. minor: charge_gpu/README.md:231. The timings "the charge part 17.1 s and 15.9 s per lifetime, the modes 2.7 s
   and 0.9 s" do not agree with the JSONL rows (charge_s 17.06 and 16.12, modes_s 2.78 and 0.84). Fix: 17.1 s and
   16.1 s, 2.8 s and 0.8 s. Also README:140 gives 1.0016 at 0.65 V, but the bench and a reviewer rerun give 1.0015
   (rounding).
3. minor: charge_gpu/README.md:287-289. "The device Poisson step gains 1.5x and 2.0x" is the ratio of the total
   Gummel solve times (3.92/2.645 and 6.614/3.334). These include the CPU continuity steps and the JIT compile of the
   first call. "1e-10 (10 nm) and 6e-10 (5 nm)" mixes the GPU rows (9.5e-11 for both) and the CPU rows (3.3e-10 and
   5.6e-10). Also, one Newton continuation step on the CPU costs about 0.8 s (17.2 s / 21 steps). The GPU Gummel
   solve at one bias costs 2.6 s, so the GPU path is not faster yet. Fix: write "the Gummel solve gains 1.5x and
   2.0x (with compile)", give the GPU and CPU numbers separately, and state that Newton on the CPU is faster for
   now.
4. minor: charge_gpu/tests/test_drift_diffusion.py:133. The Shockley test uses abs=0.01, and the ratio at 0.55 V is
   1.0099 (margin 1e-4). A small change in a constant or in the grid makes the test fail, but the physics stays
   correct. Fix: test 0.6 to 0.75 V at 1 % and 0.55 V at 1.5 %, or give the reason for the tight margin.
5. minor: charge_gpu/README.md:249. "The carriers rise by about exp(V / 2 V_T) per volt at 0.8 V" uses the wrong
   unit. The JSONL gives x2.33 from 0.80 to 0.85 V, and exp(0.05 / 2 V_T) = x2.63. Fix: "rise approximately as
   exp(V / 2 V_T) near 0.8 V".
6. minor: charge_gpu/src/charge_gpu/drift_diffusion.py:427 (`x_currents`). The function counts only x faces, so it
   gives the terminal current only for contacts on xmin/xmax. With ymin/ymax contacts the values do not have a
   physical meaning. Fix: document this, or raise an error when a contact is on ymin/ymax.
7. minor: charge_gpu/src/charge_gpu/drift_diffusion.py:490 (`sweep`). An exception in `solve` (for example a
   singular factor in `splu`) is not caught, so the step does not halve. A `guess=` in **kw collides with the
   internal guess (TypeError). Fix: catch the solver exception (RuntimeError) as a failed step, and reject `guess`
   in kw.

Observation (no finding, the README discloses it): at 10 ns and 1.0 V, 15.61 of 17.48 A/m is minority-carrier
current into the ideal ohmic contacts (reviewer rerun). So the 10 ns P_pi values depend strongly on the 0.95 um
contact regions and on the ideal contact model.

## What the reviewer tried to break
- Patch integrity: `git apply --check -R` of the patch on the working tree passes, and the SHA-256 of the patch
  equals diff_sha256. poisson.py, rc.py and modulator.py have no changes in the working tree, and drift_diffusion
  uses only their existing API (_operators, _residual_and_jdiag, _cg_mg, solver_device).
- Signs and formulas, checked by hand:
  - Scharfetter-Gummel electrons: j_n = c (B(d) n_b - B(-d) n_a). At d = 0 this is D grad n. For a constant n it
    is -D n d / h = mu n E. Correct.
  - Scharfetter-Gummel holes: j_p = c (B(d) p_a - B(-d) p_b). At d = 0 this is -D grad p. For a constant p it is
    -D p d / h. Correct.
  - Contact faces use the same formula, with the boundary node as b. Correct.
  - Residuals: sum j_n(out) - R A (div J_n = q R) and sum j_p(out) + R A (div J_p = -q R). Correct.
  - Poisson coupling: +q A for n and -q A for p. Correct.
  - SRH and its derivatives, and every Jacobian block (including the contact psi derivatives): correct.
  - Gummel continuity matrices and right-hand sides: correct.
- Contact values: n_b = n_i exp(asinh(N / 2 n_i)), p_b = n_i^2 / n_b, n_b - p_b = N. They are charge neutral and
  in equilibrium, and psi_b is the same as in poisson._operators.
- Units:
  - fc = D L / h (m^2/s), so Q fc n is in A/m, and A/m = mA/mm.
  - J = I / height for the 1-D diode.
  - Loss = 4.343 x 4 pi k / lambda (dB/cm).
  - L_pi = lambda / (2 |dneff|): 1.55e-6 / (2 x 7.23e-4) = 1.072 mm.
  - Loss in L_pi = 11.95 dB/cm x 0.1072 cm = 1.281 dB.
  - P_pi = 3.828 x 0.9 x 1.072 = 3.693 mW.
  - The Soref and Bennett values agree by hand at 0.9 V (dn -7.4e-4, 12.1 dB/cm).
- Shockley J0 by hand, with Masetti (mu_n 276.9, mu_p 160.3 cm^2/(V s) at 1e18 cm^-3): J0 = 7.547e-15 A/cm^2. This
  agrees with 7.55e-15. The coth form for a finite base with an ohmic contact is correct. The Sah-Noyce-Shockley
  estimate at 0.3 V gives a ratio of about 1.8. The code gives 1.897.
- All 25 tests of charge_gpu pass on the GPU computer (tools/gpu_run.sh, 44.6 s).
- Reviewer scratch runs on the GPU computer:
  - Symmetric long-base diode: 1.8970, 1.1445, 1.0239, 1.0099, 1.0041, 1.0015, 0.9994, 0.9908, 0.9394 at 0.3 to
    0.8 V, the same as the README. The cross-section floor is 1.9e-10 to 2.5e-10 A/m (README 2.5e-10).
  - 1e17 cm^-3, 1 us scratch claim: 1.0628, 1.0269, 1.0091, 0.9840, 0.8768, the same as the README.
  - New independent check, asymmetric diodes against Shockley:
    - N_A 1e18 / N_D 1e16 (hole injection dominates): 1.0275, 1.0117, 1.0044, 0.9973 at 0.40 to 0.55 V.
    - N_A 1e16 / N_D 1e18 (electron injection dominates): 1.0164, 1.0065, 0.9994, 0.9769.
    - So the electron and hole paths and the minority-mobility pairing are correct separately.
  - PIN current breakdown at 1.0 V: 1 ns gives 6.580 / 2.986 / 6.355 A/m (total 15.9209), and 10 ns gives
    1.203 / 0.669 / 15.609 A/m (total 17.4808). Both agree with the README.
  - PIN geometry at 20, 10 and 5 nm: see finding 1.
- README use-case table (66 values) and bench table compared one by one with the JSONL rows. All agree to the
