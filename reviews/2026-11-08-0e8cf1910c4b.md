## Findings

One major finding (a false statement in the README) and four minor findings. The physics of the change is
correct: `material_pre` of the image surface is the medium of image space, and the OPD definition with that index
is right (see "What the reviewer tried to break").

The reviewer's one GPU run (queued before the lead's GPU stop) got the GPU lock at 11:32 and ended at 11:34 EST:
154 passed in 91.8 s, and each claimed number agrees with the test prints (see below).

1. **major**: `optics_gpu/README.md:323-326` (and `:320-323`). The README says: "the optical path to the reference
   sphere uses the index of image space at the traced wavelength (Optiland: at the primary wavelength; the two
   differ only for a dispersive image space at another wavelength)". This is false.
   - Optiland 0.6.3 does not use the index of image space. `ReferenceStrategy.__init__` (wavefront/strategy.py:56)
     uses `optic.surfaces.n(primary)[-1]`, and `SurfaceGroup.n` (surfaces/surface_group.py:474-476) returns the
     `material_post` of each surface. Thus Optiland uses the medium AFTER the image surface. `add_surface` gives
     that medium the default "air", which is `IdealMaterial(1.0, 0.0)` (surfaces/factories/material_factory.py:106).
   - Thus the two codes also differ for an image space that is not dispersive, at the primary wavelength, when the
     medium before the image surface is not the medium after it (an immersed image). The README's own table row
     (README:353) shows this: the index at the primary wavelength explains 2.58 waves, but Optiland's `Wavefront`
     differs by 49.3 waves. Most of the 49.3 waves come from n = 1 (air after the image surface) against
     n = 1.42.
   - Reviewer run (`/tmp/rev9b_checks.py`, the singlet with `IdealMaterial(n=1.4)` before the image surface and
     air after it, NOT dispersive, at the primary wavelength 0.5876 um, pupil 64): this code against Optiland's
     `Wavefront` 36.3 waves; F 4.220 against Optiland's `get_working_FNO` 5.908 (ratio 1.400); MTF frequency
     step 6.401 against 4.572 cycles/mm. With `IdealMaterial(n=1.4)` also after the image surface: 4.8e-11
     waves, and F and the step are equal.
   - The README also says (`:321-323`) that the working F-number and the MTF frequency step "follow Optiland's
     code". The change (`analysis.py:175,199,205`) moves both from `image_surface.material_post` to `material_pre`.
     Optiland's `get_working_FNO` (utils.py:245) and `ScalarFFTMTF._get_mtf_frequency_steps` (mtf/fft.py:244-246)
     use `material_post` at the traced wavelength. For an immersed image, F, the PSF step dx and the MTF axis of
     this code thus differ from Optiland's by the factor n. The README does not say this. The docstring
     (`analysis.py:21-23`) gives the medium correctly, but not the wavelength rule of Optiland for items 5 and 6.
   - Fix: write in the README (and in the same words in the docstring): "Optiland 0.6.3 uses the medium after the
     image surface (air by default): at the primary wavelength for the OPD, at the traced wavelength for the working
     F-number and the MTF frequency step. This code uses the medium before the image surface (image space) at the
     traced wavelength for all three. The results are the same when the two media are the same and, for the OPD,
     the medium is not dispersive or the traced wavelength is the primary one." A test with a non-dispersive
     immersed image (`IdealMaterial(n=1.4)` before the image, air after) against `get_working_FNO` (ratio 1.4) is
     optional.

4. **minor**: `optics_gpu/src/optics_gpu/analysis.py:367-369`, `optics_gpu/tests/test_analysis.py:352`, README:326
   and the docstring item 6. The bound M >= 2 N - 1 is sufficient, but "the MTF would wrap" below it is not
   correct for the values that `fft_mtf` returns. A lag k aliases to k - M, and `fft_mtf` returns only the lags
   j < M // 2. A returned lag gets an alias from a lag |k| <= N - 1 only when j >= M - N + 1, which needs
   M <= 2 N - 4. Thus M = 2 N - 3 and 2 N - 2 give the exact returned MTF. Reviewer run (singlet, N 16): M 30,
   computed by hand with the steps of `fft_mtf`, agrees with M 64 to 4.2e-17; M 31 and 32 to 1.1e-16. The test
   comment "30 < 2 N - 1 = 31: the MTF would wrap" is thus not true. The check is safe (it refuses two grids that
   would be correct). Fix: say "the full autocorrelation would wrap; the check is conservative", or use the bound
   M >= 2 N - 3.

  GPU computer).**

    segment that ends at each surface. For the image surface, `material_pre` is
    `previous_surface.material_post` (standard_surface.py:186-191): the medium between the last surface and the
    image. The OPL of the last segment thus uses exactly the index that the change uses. Reviewer run (the
    dispersive system of the new test): dOPL / length of the last segment 1.4214871729430978 at 0.4861 um, equal

  - Rays in image space are straight lines in one homogeneous medium. The optical path from the reference sphere
    to the image is thus n times the geometric length t (real or virtual; for the singlet the sphere point lies
    behind the last surface, which is a virtual extension in image space). `OPL - n t` with this n is the optical
    path from the object to the sphere. W = (P_chief - P) / lambda_0 is the OPD in waves of the vacuum
    wavelength. This is correct.

    index (a mirror, `material="mirror"`, gets no material object there; surfaces/factories/material_factory.py:108).
