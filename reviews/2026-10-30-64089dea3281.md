## Findings

No blocker. One major finding. The physics of both packages is correct in all the checks that I made (see the next
section). The major finding is a defect in the eigensolver, and a wrong statement about it in the README.

### M1 (major): the LOBPCG residual floor is an algorithmic defect, not the working precision

- Where: `bands_gpu/src/bands_gpu/lobpcg.py:125-128`; the claims in `bands_gpu/README.md` ("Eigensolver" bullet:
  "A stall detector ends a solve at the residual floor of the working precision"; "Known limits": "the relative
  residual stalls at about 3e-7 ... The cause is not found yet").
- Cause: `p = x_new - X ov` is a subtraction with cancellation (P is small near convergence). `ap` comes from the
  same combination of `ax_new` and `ax`, not from a product. The rounding error of P (it has all |q| components)
  is therefore not in AP. SVQB then scales the small P up by 1/|P|, and the Rayleigh-Ritz matrix `S^H A S` is
  inconsistent with S. The floor goes as sqrt(eps_machine |A| / theta). It grows with the resolution.
- Repro (CPU, x64, rod lattice 64 x 64, TM, k = (0.3, 0.1), 8 bands + 4, tol 1e-11, stall detector off):
  - committed code: not converged after 300 iterations, max residual 1.5e-6;
  - the same code with line 128 changed to `p = p - _combine(ov2, x_new); ap = apply(p)`: converged in 70
    iterations, max residual 9.1e-12.
  - complex64, tol 1e-4: committed 2.9e-2 after 300 iterations; with the change 1.1e-4 after 46 iterations.
- Measured floors of the committed code in double precision: 1.2e-6 to 2.3e-6 (rods 64 x 64, TM), 1e-6 to 3e-5
  (1-D stack, 128 cells, oblique k). These are above the default `tol = 1e-6` of `solve_bands`. Thus the stall exit
  is the normal exit, and the README number 3e-7 is not general.
- Effect in single precision (the `--precision single` default of `bench/bench_bands.py`, and the README example,
  see m1): TM rods 64 x 64, 10 k points: 8 of 10 k points run to `max_iter = 300` and report not converged. The
  README example (32 x 32, 16 k points) without x64: 8 of 16 k points run 300 iterations. GPU timings measured
  now (STATUS: "GPU timings (running)") measure this defect.
- Why not a blocker: the eigenvalues stay accurate (double: 1e-15 relative against a 2000-iteration reference;
  complex64 at stalled points: 2e-7 to 4e-7 relative against complex128). The fields carry errors of the order of
  the residual.
- Suggested fix: one more product per iteration (`ap = apply(p)`), or P from the W and P parts of the Ritz
  coefficients (the Knyazev form, no cancellation). Then check the stall rule again (m2) and correct the README
  and STATUS text.

- Tests: `bands_gpu` 4 passed (3.3 s, CPU); `thermal_gpu` 4 passed (1.1 s, CPU).
- Rod-lattice reference values (the 0.7 % claim against the MPB tutorial): an independent plane-wave expansion of
  E_z with the analytic Fourier coefficients of the cylinder (Laurent rule, dense generalized eigensolve, 441 to
  3721 plane waves) gives M band 1 = 0.28066 and X band 2 = 0.41716, stable to 5 digits. This confirms the
  converged values and the claim. (The inverse rule converges slowly from above: 0.28357 and 0.42188 at 3721 plane
  waves.)
- Harmonic averaging, TE/TM and the 3-D basis: a 1-D stack (n = 3 / 1, d = 0.25) with an oblique Bloch vector
  k = (0.2, 0.35). TE of the code (H_z, E_x normal to the layers), TM (E_z) and the 3-D path (polarization None,
  both families) against the exact p- and s-polarized transfer-matrix dispersion: relative error of bands 1 to 3
